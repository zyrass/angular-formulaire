Résumé du cours

Historiquement, les Guards de routage d'Angular étaient implémentés sous la forme de classes de services enregistrées dans l'injecteur de dépendances. Désormais, Angular supporte exclusivement les guards fonctionnels, simples fonctions injectant leurs services de manière fonctionnelle via `inject()`.

1. CanDeactivate Fonctionnel

Un guard fonctionnel de type `CanDeactivate` vérifie l'état d'un composant avant de permettre à l'utilisateur de s'en aller : 

import { CanDeactivateFn } from '@angular/router';

export const pendingChangesGuard: CanDeactivateFn<MyComponent> = (component) => {
  if (component.form.dirty) {
    return confirm('Changements non enregistrés. Voulez-vous quitter ?');
  }
  return true;
};

2. Utilisation de inject() dans les Guards

Pour récupérer des dépendances sans constructeur (comme un service de session ou le routeur), on fait appel à la fonction `inject()` : 

export const authGuard: CanActivateFn = () => {
  const authService = inject(AuthService);
  const router = inject(Router);

  return authService.isLoggedIn() ? true : router.navigate(['/login']);
};

Conclusion

Les guards fonctionnels représentent une avancée majeure pour la lisibilité et l'écriture du routage dans Angular. En se passant de classes formelles, on évite le code boilerplate. De plus, ils s'associent à merveille avec `inject()`, permettant de composer et de partager facilement de petites fonctions de garde hautement spécialisées.
