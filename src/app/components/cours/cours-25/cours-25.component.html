{{ title }}

Interceptez chaque phase de vie d'un composant — création, mise à jour et destruction — pour initialiser, réagir et nettoyer.

Résumé du cours

Angular appelle des méthodes de cycle de vie à des moments précis de la vie d'un composant : lors de sa création, à chaque mise à jour de ses @Input, et lors de sa destruction.

Ordre d'exécution des hooks

1
ngOnChanges(changes: SimpleChanges)

Appelé avant ngOnInit et à chaque changement d'un @Input. Reçoit les anciennes et nouvelles valeurs.

2
ngOnInit()

Initialisation du composant. Les @Input sont disponibles. Idéal pour les appels API initiaux.

3
ngDoCheck()

Appelé à chaque cycle de détection de changement. À utiliser avec précaution (performance).

4
ngAfterContentInit() / ngAfterContentChecked()

Après que le contenu projeté (ng-content) a été initialisé/vérifié.

5
ngAfterViewInit() / ngAfterViewChecked()

Après l'initialisation de la vue et des enfants. C'est ici que @ViewChild est disponible.

✕
ngOnDestroy()

Avant la destruction du composant. Crucial pour se désabonner des Observables et éviter les fuites mémoire.

Exemple complet

export class DataComponent
  implements OnInit, OnDestroy, OnChanges {

  @Input() userId!: string;
  private sub!: Subscription;

  public ngOnChanges(changes: SimpleChanges) {
    if (changes['userId']) this.loadUser();
  }

  public ngOnInit(): void {
    this.sub = this.service.data$.subscribe(...);
  }

  public ngOnDestroy(): void {
    this.sub.unsubscribe();  ← ESSENTIEL !
  }
}

À retenir

Les 3 hooks essentiels

ngOnInit — initialisation, appels API

ngOnChanges — réagir aux @Input

ngOnDestroy — nettoyage mémoire

takeUntilDestroyed (v16+)

private destroyRef = inject(DestroyRef);

service.data$.pipe(
  takeUntilDestroyed(this.destroyRef)
).subscribe(...)

Remplace ngOnDestroy + unsubscribe.

⚠️ Fuite mémoire

Un Observable souscrit sans désabonnement continue de vivre après la destruction du composant. Toujours désabonner dans ngOnDestroy.

Conclusion

Les lifecycle hooks sont votre interface avec le moteur de rendu d'Angular. En pratique, 90% de vos besoins seront couverts par ngOnInit, ngOnChanges et ngOnDestroy. L'adoption de takeUntilDestroyed (v16+) simplifie considérablement la gestion des désabonnements et élimine une classe entière de bugs mémoire.
