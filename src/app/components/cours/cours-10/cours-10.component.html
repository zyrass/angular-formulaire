Résumé du cours

L'un des plus grands atouts de l'approche réactive d'Angular est l'exposition sous forme d'observables (`Observable`) des flux d'événements liés aux formulaires.

1. Écouter les changements de valeurs : `valueChanges`

La propriété `valueChanges` est un flux qui émet la nouvelle valeur du champ (ou du formulaire) à chaque frappe de clavier ou modification programmatique : 

          TS (v17/v18)
          this.form.valueChanges.subscribe((newValue) => {
            console.log('Nouvelle valeur :', newValue);
          });
        
          TS (v19/v20)
          import { toSignal } from '@angular/core/rxjs-interop';

          // Conversion de l'Observable en Signal
          public searchVal = toSignal(this.form.valueChanges);
        
          TS (v21)
          // Utilisation directe du Signal natif exposé par le FormGroup
          public searchVal = this.form.valueSignal;

2. Écouter l'état de validation : `statusChanges`

La propriété `statusChanges` émet une chaîne de caractères (`'VALID'`, `'INVALID'`, `'PENDING'` ou `'DISABLED'`) dès que le statut de validation du contrôle change : 

          TS (v17/v18)
          this.form.statusChanges.subscribe((newStatus) => {
            console.log('Statut :', newStatus);
          });
        
          TS (v19/v20)
          import { toSignal } from '@angular/core/rxjs-interop';

          // Conversion de l'Observable en Signal
          public formStatus = toSignal(this.form.statusChanges);
        
          TS (v21)
          // Utilisation directe du Signal natif pour le statut de validation
          public formStatus = this.form.statusSignal;

3. Libération de ressources

**Très important** : Pensez toujours à vous désabonner de ces flux dans le hook de cycle de vie `ngOnDestroy()` pour éviter des fuites de mémoire (memory leaks).

💡 **Avantage des Signaux** : Contrairement aux Observables classiques, l'utilisation de `toSignal()` ou des propriétés de signaux natifs (`valueSignal`) libère automatiquement les ressources lorsque le composant est détruit. Aucun désabonnement manuel n'est requis dans `ngOnDestroy()` !

Conclusion

flux réactifs :
Les flux observables permettent d'implémenter facilement des fonctionnalités avancées comme de l'autocomplétion (avec l'opérateur `debounceTime` de RxJS).
Désabonnement :
Toujours détruire les abonnements lors de la destruction du composant (`ngOnDestroy`) pour s'assurer que l'application ne consomme pas de mémoire inutilement.
