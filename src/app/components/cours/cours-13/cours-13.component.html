Résumé du cours

Les Signals introduisent une réactivité à grain fin (fine-grained reactivity) dans Angular. Contrairement à RxJS, ils n'exigent pas de souscription explicite (`subscribe`) ni d'opérateurs complexes pour la lecture et le calcul synchrone des états.

1. Les trois concepts clés

  • signal(initialValue) : Conteneur réactif pour une valeur modifiable via `.set()` ou `.update()`.
  • computed(() => readSignals) : Signal en lecture seule calculé dynamiquement à partir d'autres signaux. Recalculé uniquement si les signaux dépendants changent (mémoïsation).
  • effect(() => sideEffects) : Bloc de code exécuté automatiquement chaque fois qu'un signal lu à l'intérieur change de valeur (idéal pour le logging, les synchros locales).

2. L'interopérabilité RxJS / Signals

Pour lier les flux asynchrones complexes (API HTTP, Websockets) aux signaux de l'interface, on utilise les fonctions d'interopérabilité : 

        TS (v18+)
        import { toSignal, toObservable } from '@angular/core/rxjs-interop';

        // Convertir un Observable RxJS en Signal
        public ticks = toSignal(this.tickInterval$, { initialValue: 0 });

Conclusion

Les Signals ne remplacent pas RxJS pour la gestion des événements complexes et asynchrones, mais ils le remplacent avantageusement pour tout ce qui concerne le rendu synchrone et l'affichage d'état local. L'utilisation intelligente de `toSignal()` permet de lier simplement vos streams de données à l'interface graphique tout en garantissant des performances optimales sans gaspillage de cycle processeur.
