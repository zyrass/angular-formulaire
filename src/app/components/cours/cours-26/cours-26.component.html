{{ title }}

Comprendre le mécanisme qui met à jour la vue, et comment l'optimiser avec OnPush et l'immutabilité.

Résumé du cours

La Change Detection est le mécanisme par lequel Angular détecte les changements dans les données et met à jour le DOM en conséquence. Par défaut, Angular vérifie l'intégralité de l'arbre de composants à chaque événement.

1. Stratégie Default (comportement par défaut)

// Angular vérifie TOUS les composants à chaque :
// - Événement DOM (click, input...)
// - Réponse HTTP
// - setTimeout / setInterval
// - Promise résolue

@Component({
  changeDetection: ChangeDetectionStrategy.Default  ← implicite
})

2. Stratégie OnPush — optimisation

@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class UserCardComponent {
  @Input() user!: User;
}

// Angular ne vérifie ce composant QUE si :
// 1. La référence d'un @Input change (nouvelle instance)
// 2. Un événement est déclenché dans ce composant
// 3. Un Observable via async pipe émet une valeur
// 4. markForCheck() / detectChanges() est appelé manuellement

3. Immutabilité — la clé d'OnPush

// ❌ MAL : mutation d'objet — OnPush ne détecte PAS
this.user.name = 'Alain';

// ✅ BIEN : nouvelle référence — OnPush détecte
this.user = { ...this.user, name: 'Alain' };

// ❌ MAL : push sur tableau existant
this.items.push(newItem);

// ✅ BIEN : nouveau tableau
this.items = [...this.items, newItem];

4. Déclenchement manuel

private cdr = inject(ChangeDetectorRef);

// Marque le composant pour vérification au prochain cycle
this.cdr.markForCheck();

// Force la vérification immédiate
this.cdr.detectChanges();

À retenir

Default vs OnPush

DefaultVérifie tout → lent
OnPushVérifie si besoin → rapide

Signals = Zoneless

Avec les Signals (v16+), Angular peut s'affranchir de Zone.js et ne mettre à jour que les composants qui consomment un signal modifié — la CD la plus granulaire possible.

💡 Conseil pro

Appliquez OnPush à tous vos composants présentationnel (purs). Réservez Default aux composants conteneurs qui gèrent l'état.

Conclusion

La Change Detection est souvent la source principale de problèmes de performance dans les applications Angular de taille moyenne à grande. Adopter OnPush et les principes d'immutabilité dès le départ vous évitera des refactorisations douloureuses. L'avènement des Signals en v16+ représente l'évolution naturelle vers une réactivité fine-grained sans Zone.js.
