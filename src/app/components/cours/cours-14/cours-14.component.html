Résumé du cours

Depuis les dernières versions d'Angular, l'ancien module `HttpClientModule` est abandonné au profit de la configuration fonctionnelle `provideHttpClient()`. Les intercepteurs, autrefois basés sur des services de classe complexes, sont devenus de simples fonctions légères enregistrées globalement.

1. Enregistrement Fonctionnel

Les intercepteurs fonctionnels sont déclarés dans le fichier de bootstrap/config de l'application (ex: `app.config.ts`) : 

export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient(
      withInterceptors([authInterceptor])
    )
  ]
};

2. Exemple d'Intercepteur Fonctionnel (v18+)

Un intercepteur fonctionnel reçoit la requête (`HttpRequest`) et le gestionnaire suivant (`HttpHandlerFn`) et retourne un flux observable d'événements HTTP : 

import { HttpInterceptorFn } from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  // Cloner la requête pour insérer le token d'autorisation
  const clonedReq = req.clone({
    headers: req.headers.set('Authorization', 'Bearer token-123')
  });
  return next(clonedReq);
};

Conclusion

L'unification de HttpClient vers des configurations fonctionnelles est un atout majeur pour l'optimisation des applications modernes. L'absence de classes d'intercepteurs superflues simplifie grandement l'injection de dépendances via `inject()` et permet un arbre de dépendances (tree-shaking) ultra-efficace, réduisant drastiquement la taille finale de votre application en production.
