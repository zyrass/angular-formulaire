{{ title }}

Centralisez la logique métier dans des services injectables et maîtrisez le système DI d'Angular.

Résumé du cours

Un service Angular est une classe singleton qui centralise la logique métier, les appels HTTP et l'état partagé. L'injection de dépendances (DI) permet à Angular de fournir automatiquement ces services aux composants qui en ont besoin.

1. Créer un service injectable

import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'  ← singleton global, tree-shakable
})
export class UserService {
  private users: User[] = [];

  public getAll(): User[] {
    return this.users;
  }

  public add(user: User): void {
    this.users.push(user);
  }
}

2. Injecter dans un composant

// Méthode classique — constructeur (v2–v17)
export class UserListComponent {
  constructor(private userService: UserService) {}

  public users = this.userService.getAll();
}

// Méthode fonctionnelle — inject() (v14+, recommandée)
export class UserListComponent {
  private userService = inject(UserService);
  public  users = this.userService.getAll();
}

3. Scope des providers

providedIn: 'root'

Singleton global — une seule instance pour toute l'app. Recommandé pour les services HTTP, auth, etc.

providers: [MyService] dans @Component

Instance dédiée au composant et ses enfants. Idéal pour les services à état locaux.

providers: [MyService] dans @NgModule

Partagé dans le module. Utilisé pour lazy-loaded features.

À retenir

Génération CLI

ng g service shared/services/user

inject() vs constructeur

inject() peut être utilisé en dehors du constructeur (dans les champs de classe), ce qui simplifie l'héritage et réduit le boilerplate.

Tokens DI avancés

InjectionToken — valeurs scalaires

@Optional() — dépendance nullable

@Self() — cherche uniquement localement

@SkipSelf() — cherche dans le parent

Conclusion

L'injection de dépendances est l'une des forces majeures d'Angular. Elle encourage la séparation des préoccupations (SoC) et facilite les tests unitaires en permettant de remplacer les services réels par des mocks. Adoptez inject() systématiquement dans vos nouveaux projets — c'est l'approche moderne, plus compatible avec la zoneless architecture et les Signals.
