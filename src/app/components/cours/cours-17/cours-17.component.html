Comprendre la structure d'un projet Angular, ses décorateurs et le choix entre NgModule et Standalone.

Résumé du cours

Angular est un framework opinionné basé sur TypeScript. Chaque application Angular est composée d'un arbre de composants orchestrés par un système de modules ou de configuration standalone.

1. Structure d'un projet Angular CLI

Après ng new mon-projet, vous obtenez :

mon-projet/
├── src/
│   ├── app/
│   │   ├── app.component.ts       ← Composant racine
│   │   ├── app.module.ts           ← Module racine (NgModule)
│   │   └── app-routing.module.ts   ← Configuration des routes
│   ├── main.ts                  ← Point d'entrée bootstrap
│   └── index.html              ← Shell HTML de l'app
└── angular.json               ← Config du CLI Angular

2. Les décorateurs essentiels

Angular s'appuie massivement sur les décorateurs TypeScript pour annoter les classes :

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css'],
})
export class AppComponent {
  title = 'mon-projet';
}

// Autres décorateurs clés :
@NgModule    ← Déclare un module Angular
@Injectable  ← Marque une classe comme service injectable
@Pipe        ← Déclare un pipe de transformation
@Directive   ← Déclare une directive d'attribut

3. NgModule vs Standalone (v15+)

NgModule (v2 → v17)

  • • Modules explicites (app.module.ts)
  • • declarations, imports, providers
  • • Utilisé dans la majorité des projets en production
  • • Verbeux mais structurant pour les grandes équipes

Standalone (v15+ → défaut v18)

  • • standalone: true dans @Component
  • • Imports directs dans le composant
  • • Moins de boilerplate
  • • Recommandé pour les nouveaux projets v18+

À retenir

Le cycle de vie d'une app Angular

  1. 1. Le navigateur charge index.html
  2. 2. main.ts bootstrap l'AppModule
  3. 3. Angular instancie AppComponent
  4. 4. Le selector <app-root> est remplacé par le template
  5. 5. Le router prend le relai et affiche les routes

Commandes CLI indispensables

ng generate component Créer un composant
ng generate service Créer un service
ng build Build production
ng test Lancer les tests

💡 Conseil

Dans ce parcours, nous utilisons l'architecture NgModule car elle reste dominante en environnement professionnel. Chaque concept s'applique à Standalone avec de légères différences syntaxiques.

Conclusion

Comprendre l'architecture d'Angular est le socle indispensable avant d'écrire votre première ligne de code. La structure modulaire garantit une organisation claire des responsabilités, tandis que le mode Standalone simplifie progressivement cette architecture pour les projets modernes. Dans tous les cas, les décorateurs TypeScript restent le cœur expressif d'Angular.
