L'architecture moderne d'Angular — composants autonomes sans NgModule, disponible depuis v15 et par défaut en v18.

Résumé du cours

Les Standalone Components (v15+) permettent de créer des composants qui déclarent leurs propres dépendances directement, sans passer par un NgModule. Depuis Angular 18, c'est la configuration par défaut.

ℹ️

Note pédagogique — Ce projet de formation utilise l'architecture NgModule (v17) pour illustrer les fondations classiques encore présentes dans la grande majorité des bases de code professionnelles. En production sur Angular 18+, vous démarreriez directement avec bootstrapApplication() et des composants standalone.

1. Composant Standalone

@Component({
  selector: 'app-user-list',
  standalone: true,             ← clé de la standalone
  imports: [
    CommonModule,             ← ou NgIf, NgFor individuellement
    ReactiveFormsModule,
    RouterModule,
    UserCardComponent,        ← import direct d'un autre standalone
  ],
  templateUrl: './user-list.component.html',
})
export class UserListComponent { ... }

2. Bootstrap sans NgModule

// main.ts — Angular 18+ par défaut
bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes),
    provideHttpClient(),
    provideAnimations(),
  ],
}).catch(err => console.error(err));

3. Migration NgModule → Standalone

// Commande automatique de migration (Angular CLI)
ng generate @angular/core:standalone

// Options disponibles :
// --mode=convert-to-standalone
// --mode=prune-ng-modules
// --mode=standalone-bootstrap

4. Imports granulaires (v15+)

// Au lieu de CommonModule (tout importer)
import { NgIf, NgFor, AsyncPipe } from '@angular/common';

@Component({
  standalone: true,
  imports: [NgIf, NgFor, AsyncPipe],  ← seulement ce dont on a besoin
})

À retenir

NgModule vs Standalone

✗NgModule : déclarations centralisées
✓Standalone : auto-suffisant, tree-shakable
✓Standalone : meilleur pour le lazy loading
✓Standalone : défaut Angular 18+

Génération standalone

ng g c my-comp --standalone ng g s my-service

🚀 v18+ par défaut

Dans Angular 18+, ng new génère directement une application standalone sans NgModule. C'est la direction officielle du framework.

Conclusion

Les Standalone Components marquent une évolution majeure dans l'architecture Angular. En éliminant la friction des NgModules pour les projets modernes, Angular s'aligne sur les standards du web (Web Components) et simplifie considérablement l'expérience développeur. Que vous mainteniez un projet NgModule ou démarriez un nouveau projet standalone, comprendre les deux paradigmes est aujourd'hui indispensable.
