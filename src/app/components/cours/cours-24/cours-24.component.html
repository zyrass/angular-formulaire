@Input, @Output, EventEmitter et @ViewChild — les patterns de communication parent-enfant en Angular.

Résumé du cours

Dans un arbre de composants Angular, les données coulent vers le bas via @Input() et remontent vers le haut via @Output() + EventEmitter.

1. @Input() — du parent vers l'enfant

// Composant enfant
export class UserCardComponent {
  @Input() public user!: User;
  @Input() public isHighlighted = false;

  // v17+ : signal input (recommandé)
  public user = input.required<User>();
  public isHighlighted = input(false);
}

<!-- Utilisation dans le parent -->
<app-user-card
  [user]="currentUser"
  [isHighlighted]="true"
/>

2. @Output() — de l'enfant vers le parent

// Composant enfant
export class SearchBarComponent {
  @Output() public searched = new EventEmitter<string>();

  public onSearch(term: string): void {
    this.searched.emit(term);
  }

  // v17+ : output() fonctionnel
  public searched = output<string>();
}

<!-- Écoute dans le parent -->
<app-search-bar (searched)="onSearch($event)" />

3. @ViewChild — accès direct à un enfant

@ViewChild(SearchBarComponent) searchBar!: SearchBarComponent;
@ViewChild('myInput') inputRef!: ElementRef;

public ngAfterViewInit(): void {
  this.searchBar.focus();
  this.inputRef.nativeElement.focus();
}

À retenir

Schéma de flux

🔽 Parent → Enfant : [input]

🔼 Enfant → Parent : (output)

📡 Sibling ↔ Sibling : Service partagé

🌍 App-wide : Service singleton / Signals

@ContentChild

Accède à un contenu projeté via <ng-content>. Disponible dans ngAfterContentInit.

⚠️ Évitez les chaînes longues

Trop de niveaux @Input/@Output = "props drilling". Préférez un service ou les Signals pour l'état partagé profond.

Conclusion

La communication parent-enfant via @Input/@Output est le pattern fondamental d'Angular pour des composants découplés et réutilisables. Pour les communications entre composants non liés hiérarchiquement, le service partagé reste la solution standard avant d'adopter les Signals (v16+) pour un état réactif fine-grained.
