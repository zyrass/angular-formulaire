{{ title }}

*ngIf, *ngFor, *ngSwitch en v17 et leur équivalent moderne @if, @for, @switch en v17+.

Résumé du cours

Les directives structurelles modifient le DOM en ajoutant, supprimant ou répétant des éléments. Elles commencent par un astérisque * en syntaxe classique, ou par un @ en syntaxe de contrôle de flux (v17+).

1. Conditionnelle — *ngIf / @if

// Syntaxe classique (v2–v17)
<div *ngIf="isLoggedIn; else guestBlock">
  Bienvenue, {{ '{{' }} userName {{ '}}' }} !
</div>
<ng-template #guestBlock>
  <p>Veuillez vous connecter</p>
</ng-template>

// Nouvelle syntaxe de contrôle de flux (v17+)
@if (isLoggedIn) {
  <p>Bienvenue !</p>
} @else {
  <p>Veuillez vous connecter</p>
}

2. Boucle — *ngFor / @for

// Syntaxe classique
<li *ngFor="let item of items; let i = index; trackBy: trackByFn">
  {{ '{{' }} i {{ '}}' }} — {{ '{{' }} item.name {{ '}}' }}
</li>

// Nouvelle syntaxe (v17+)
@for (item of items; track item.id) {
  <li>{{ '{{' }} item.name {{ '}}' }}</li>
} @empty {
  <p>Aucun élément</p>
}

3. Switch — *ngSwitch / @switch

@switch (userRole) {
  @case ('admin') {
    <app-admin-panel />
  }
  @case ('user') {
    <app-user-dashboard />
  }
  @default {
    <app-guest-view />
  }
}

4. ng-container : wrapper invisible

<!-- ng-container n'ajoute pas de nœud DOM -->
<ng-container *ngIf="isAdmin">
  <h2>Admin Panel</h2>
  <button>Supprimer</button>
</ng-container>

À retenir

Variables locales *ngFor

index — position 0-based

first — boolean premier item

last — boolean dernier item

even — boolean index pair

odd — boolean index impair

trackBy : performance !

public trackById(i: number, item: Item) {
  return item.id;
}

Évite la re-création complète du DOM lors des updates.

💡 v17+ : @for obligatoire

Avec la nouvelle syntaxe, track est obligatoire. Utilisez track item.id ou track $index au minimum.

Conclusion

Les directives structurelles sont le système nerveux de votre template Angular. La nouvelle syntaxe de contrôle de flux (v17+) — @if, @for, @switch — est plus lisible, plus performante et plus TypeScript-friendly que les anciennes directives *ngIf et *ngFor. Pour les nouveaux projets, privilégiez systématiquement la syntaxe @ même si vous restez compatibles avec l'ancienne.
