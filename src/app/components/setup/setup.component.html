Installation, Config & Design System

1. Prérequis & Angular CLI

Pour démarrer avec Angular, vous devez installer Node.js puis installer le CLI globalement. Voici la matrice de compatibilité recommandée :

Version Angular Node.js requis Commande de création
Angular v17 v18.13.0 / v20.x ng new mon-projet
Angular v18 v18.19.0 / v20.x ng new mon-projet
Angular v19 - v21 v20.11.0 / v22.x ✅ ng new mon-projet --zoneless
Ce cours (v17) Node 22 LTS ⭐ Recommandé ng new mon-projet

⚡ Installer Node 22 LTS — Recommandé pour ce cours

Node 22 est la version Active LTS — sécurité renforcée, performances améliorées et compatibilité garantie avec Angular v17 à v21. C'est la version utilisée pour ce mémoire.

Via nvm (macOS / Linux / WSL) 
nvm install 22
nvm use 22
nvm alias default 22
Via nvm-windows (Windows) 
nvm install 22
nvm use 22
Vérification 
node --version   # → v22.x.x
npm --version    # → 10.x.x

💡 Créer le projet sans installer les modules (si Node 22 pas encore actif)

Si vous n'avez pas encore Node 22 d'actif, utilisez le flag --skip-install pour générer la structure du projet sans lancer npm install. Vous basculez ensuite vers Node 22, puis installez les dépendances.

Étape 1 — Créer le projet sans installer 
ng new mon-projet --skip-install
cd mon-projet
Étape 2 — Activer Node 22 
nvm use 22
node --version   # → v22.x.x ✅
Étape 3 — Installer les dépendances 
npm install

Pourquoi ? Angular CLI installe automatiquement les node_modules après ng new. Avec --skip-install, vous gardez le contrôle sur la version Node utilisée pour l'installation.

2. Les bases des Templates : Évolution de la Syntaxe

Le rendu conditionnel et les boucles ont subi une révolution majeure à partir d'Angular v17 avec l'arrivée du Control Flow natif, qui remplace les anciennes directives structurelles.

Les Conditions : Du *ngIf au @if

Ancienne Syntaxe (Requiert CommonModule) 
<div *ngIf="isLoaded">
  Contenu affiché
</div>
<div *ngIf="!isLoaded">
  Chargement...
</div>
Nouvelle Syntaxe (Native et Optimisée) 
@if (isLoaded) {
  Contenu affiché
} @else {
  Chargement...
}

Les Boucles : Du *ngFor au @for

Ancienne Syntaxe 
<div *ngFor="let item of items; let i = index">
  {{ '{{ i }} : {{ item.name }}' }}
</div>
Nouvelle Syntaxe (Clé "track" obligatoire) 
@for (item of items; track item.id) {
  <div>{{ '{{ $index }} : {{ item.name }}' }}</div>
} @empty {
  <p>Aucun élément disponible.</p>
}

3. Intégration du CSS

Angular supporte nativement différents formats de préprocesseurs (CSS, SCSS, Sass, Less). Le framework utilise par défaut l'Encapsulation d'Émulation CSS pour isoler les styles.

Option A : Utilisation du CSS Classique (Vanilla)

Le CSS standard est écrit au niveau du composant et configuré dans le décorateur `@Component`. Les styles sont limités à ce seul composant. 

@Component({
  selector: 'app-card',
  templateUrl: './card.component.html',
  styleUrls: ['./card.component.css'] // Styles locaux
})

Option B : Tailwind CSS v3 (PostCSS classique)

Pour utiliser Tailwind v3, configurez le scanner de fichiers via le fichier de configuration JS.

1. Installation : 
npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init
2. Configuration (tailwind.config.js) : 
content: [
  "./src/**/*.{{ '{' }}html,ts{{ '}' }}", // Scanner les fichiers
],
3. Import Global (styles.css) : 
@tailwind base;
@tailwind components;
@tailwind utilities;

Option C : Tailwind CSS v4 (CSS-First / Moderne)

Tailwind v4 supprime tailwind.config.js au profit d'une configuration 100% basée sur CSS et le nouveau moteur de compilation Rust.

1. Installation : 
npm install tailwindcss @tailwindcss/postcss postcss
2. Activer dans postcss.config.js : 
module.exports = {
  plugins: {
    '@tailwindcss/postcss': {},
  }
}
3. Configuration Directe (styles.css) : 
@import "tailwindcss";

/* Variables CSS du thème */
@theme {
  --color-indigo-500: #4f46e5;
}

Mon Conseil Design

Que vous choisissiez le CSS natif pour garder un contrôle d'encapsulation absolu sur vos composants, ou Tailwind CSS pour accélérer le prototypage réactif de vos interfaces, l'important est de rester homogène. L'arrivée du nouveau control flow (@if / @for) réduit le besoin d'importer le `CommonModule` dans chaque composant standalone, améliorant d'environ 10% le temps de compilation de vos bundles d'application.
